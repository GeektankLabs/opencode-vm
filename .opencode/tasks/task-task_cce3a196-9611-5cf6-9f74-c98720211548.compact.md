## Confirmed decisions (implemented in r20)

- Three labelled checkpoints as the single shared vocabulary across the skill:
  - `CONCEPT_READY` — agent's terminal return on a successful file creation/reconciliation (paths, `Task-ID`s from each head block, short summary).
  - `REGISTERED` — orchestrator's first internal checkpoint; both roles bound via `register_task_document` and read back via `get_task_documents` as `state:available`.
  - `BOARD_MOVED` — orchestrator's second internal checkpoint; Board move tool returned success and readback confirmed `in_progress`.
- The agent's `CONCEPT_READY` is the start of the orchestrator's follow-through, not its end. The Board never moves before `REGISTERED`.
- Orphan-files recovery path is explicit: detect → verify `Task-ID` from each head block → reuse → register → read back → move. No recreate, no rename, no legacy artifact links. Foreign `Task-ID` at canonical path is a collision that stops the run with a path-decision request.
- `CONCEPT_READY` requires verified file content (actual `Task-ID` from each file's head block), not just paths. Path-only reports are rejected before any registration call.
- New reference `references/initialization-follow-through.md` is the canonical document for the labelled checkpoints, the orphan-files recovery path and the failure-shape catalogue.
- Seven new regression rows in `references/regression-scenarios.md`: the six planned cases plus approval interruption preserving the last successful step.
- Flow-level test `test_initialization_follow_through_sequence_walks_orchestrator_side` models the ordered checkpoints against in-memory fakes. Its cases cover clean run, premature-advance guard, partial registration and retry of only the missing role, uncertain move, orphan reuse, foreign-ID collision, unavailable/wrong-path/missing-revision document readbacks, unsuccessful Board readback, and path-only reject.
- New vocabulary test `test_initialization_follow_through_vocabulary_and_text_markers` asserts that the labelled names appear in SKILL.md, the new reference and the regression rows, and that the row content captures the no-silent-Board-advance and the no-recreate-or-rename guarantees.
- Skill bundle revision bumped from `2026-09-29-r19` to `2026-09-29-r20`; `bundle.json` `files` updated; `latest.json` and `opencode-session-orchestrator.zip.sha256` regenerated via `python3 scripts/build-chatgpt-skill.py`; `python3 scripts/build-chatgpt-skill.py --check` passes.
- No new background process, polling loop, daemon, scheduler, MCP tool, OpenCode core patch, `opencode-vm.sh` change or adapter change.

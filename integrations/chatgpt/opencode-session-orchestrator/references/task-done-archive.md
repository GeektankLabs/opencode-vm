# Verified task Done and last-open-linked-task archive

This is a narrow skill-managed follow-through of an **authorized task-Done operation**, not a watcher of arbitrary Board UI changes, background timer, backend Board/session coupling or new permission grant. Business outcome/result review and actual Done authority must already exist. Do not auto-mark Done from agent completion, review PASS, idle, queue receipt or this policy. Preserve original task/session/message/result IDs and secured return before any archive; host/security approvals remain independent.

## Ordered conservative flow

1. **DONE_AUTHORITY:** establish the selected connector/repository, exact closed task and current authorized Done workflow; secure complete relevant original-result evidence and required handback. If authority, outcome/read coverage or handback is missing/uncertain, zero archives. A clarification answer must be secured/returned first. An explicit standalone manual archive request uses its existing separate workflow, not invented task links or this automatic policy.
2. **DONE_READBACK:** independently read the exact task with the discovered Board tool after its authorized status operation; require persisted native `done`, not the move receipt alone. Uncertain move => reconcile exact status, no blind move retry, new task or rollback. If Done cannot be verified, stop archive follow-through.
3. **EXACT_LINKS:** read this closed task's explicit links and deduplicate exact `session_id`s, retaining their message/result references. Missing links => report no targets, zero archive calls. Never infer targets from title, parent/child, current manager, unrelated queue entry or another task. Process each actual linked session independently; invalid/unavailable link evidence is a reported gap, not a guessed session.
4. **REFERENCE_COVERAGE:** use the discovered repository-wide reverse lookup for that session with **all statuses and all Board Projects/workstreams**. Omit status/query/updated-since/project/workstream narrowing; ensure terminal tasks included if the contract exposes that option. Current opencode-vm `list_project_tasks` success is a complete bounded local scan only within its documented limits; `TASK_SEARCH_INCOMPLETE` is a gap, not an empty result. Other connectors require their own complete pagination/coverage evidence. Any `todo` or `in_progress` reference, including an open package/master in another workstream, blocks automatic archive. Only `done` references don't block. Unknown status, transfer-pending, incomplete/error/foreign repository coverage => skip this session, no narrowing to manufacture eligibility.
5. **SESSION_ELIGIBILITY:** exact `get_session`/equivalent must prove exposed eligible project root (not foreign/child/manager), idle, no permissions/questions, no concurrent write and checkable admission/correlated receipt evidence. A remaining guarded message or uncheckable/unknown/unresolved receipt => conservative skip; never supersede/abort/force/answer security input to make eligible. Missing evidence/tool is a prerequisite/skip, not no-input proof. Known archived ID via supported `include_archived:true` => report already archived, not a new archive success.
6. **FRESH_RECHECK:** immediately before mutation reread the closed task's Done/links, complete reverse coverage and exact session eligibility. If the exact fresh session is already archived, report its existing state without a new archive call. Link removal, reopened task/new open reference, busy/input/guard drift or partial reads => skip without changing Done. This is a best-effort cooperating **non-atomic boundary**, not UI/MCP CAS or a transaction; disclose remaining races rather than inventing locks/backend semantics.
7. **ARCHIVE_ONCE:** invoke the existing discovered archive tool once per eligible exact session. Require exact-ID archived timestamp readback, using `get_session(include_archived:true)` when supported. Uncertain/lost archive reply => read that same ID first; verified archived state reconciles success, otherwise report uncertain/not verified, **no blind retry** or duplicate session/action. A previously attempted uncertain archive on reentry is reconciled before another admission. Never recreate/unarchive/rollback Done automatically; archive preserves history, not deletion.
8. **REPORT_OUTCOMES:** give per-session archived/already archived/skipped/uncertain with exact evidence/reason, preserving task Done even when archive is blocked. Deduplicate presentation/action receipts under existing selected-channel rules. One blocked session does not force others; report any missing targets/coverage. No watcher, automatic later retry or post-turn monitoring promise; a later authorized management pass may revalidate facts.

Reference lookup example for the currently discovered opencode-vm schema (omit unsupported optional fields on older connectors, but never narrow coverage):

```json
{"session_id":"<linked_session_id>","include_terminal":true}
```

`project_id` / `board_project_id` would select a Board Project, not expand repository scope; do not supply either for this coverage check. A filtered empty list does not prove last-open-task closure. Eligibility/source guards remain skill checks even if a backend archive call only checks idle/pending: never presume it resolves historical receipts or supplies Board-wide atomicity.

## Authority and recovery limits

The authorized Done flow now includes this documented eligible archive follow-through; no redundant separate archive confirmation ceremony is added inside it. Explicit user exclusions/no-archive, stricter package contracts and real host/security controls win. Outside it, generic manual archive remains a separate **explicitly requested** operation. Pure status/read/planning/start-only calls do not activate Done or archival. Package member completion doesn't close an open package; its session references count until actually closed. Preserve selected project/channel identity and all r40 agent/profile/scope/readback rules; no model/runtime or backend/global default change.

Fake-connector/source-order tests cover complete last/first reference cases, cross-workstream/package open refs, done-only/missing/duplicate links, independent multi-session blockers, partial/unknown coverage, busy/input/write/guard/unknown admission, secured handback, uncertain Done/archive, fresh drift and archived-by-ID reconstruction. These do not run live archives or prove Hosted/non-atomic race elimination. Actual runtime operations require their normal authorized connected workflow, never this implementation/test assignment itself.
